# Every failure mode this runner has hit

One table, drawn from two documents that record failures in different formats:
`AGENTS.md`'s numbered "Failure modes this runner has already paid for" (1–9,
from a 24-task run against Lumina) and `docs/findings.md` sections 3
(correctness and safety, 3.1–3.16) and 6 (process findings, 6.1–6.5, from the
first live epic and twelve lanes).

This file is a projection, not a source. Both originals stay authoritative for
their own numbering and their own prose — nothing here is renumbered, and the
IDs below are the IDs those documents use. Where a row says OPEN, no code
guards it today.

## The numbering disagreement, stated

`docs/findings.md` 5.2 records it, and it is unresolved: **`docs/epic-schema.md`
calls infra-versus-bad-ticket failure mode 4. `AGENTS.md` calls it 7, and its
own #4 is a different, still-OPEN failure (a hard quota retried as a soft rate
limit).** So a reference to "failure mode 4" means one thing in `epic-schema.md`
and another in `AGENTS.md`. Lane I addressed both readings and closed neither,
correctly declining to edit `AGENTS.md` on unwired code.

Nothing in this file picks a winner. When a document says "failure mode N",
check which document it means. `AGENTS.md`'s numbering is the one used below,
because it is the one the failure modes themselves are written under.

Two further naming traps worth knowing before reading the table: `AGENTS.md`'s
IDs are bare integers and `findings.md`'s are dotted (`3.4`), so they never
collide; and the two documents overlap in subject matter exactly once — a
session/quota limit killing a lane (`AGENTS.md` #4, `findings.md` 6.5) — where
they describe different halves of the same event and neither cross-references
the other.

## What is deliberately not in the table

`findings.md` **3.10** ("The end-to-end walk now has a test") records a gap in
coverage rather than a failure with a symptom, so it has no "what you would see"
to put in a row. It is worth reading anyway: `scripts/epic-e2e.test.mjs` exists
because epic #3 failed five times on things every unit test was green about, and
three of its assertions were written by first reproducing a live bug and
watching them fail. It also names two traps that cost time while writing it —
the fake agent sniffed for the word "contradiction" to recognise the
plan-reviewer, which the ledger's own prompt block contains; and reporting
agents must put their JSON in `result` as well as the message, because
`agent-stats.mjs` prefers `result`.

Sections 1, 2, 4 and 5 of `findings.md` are out of scope here: 1 and 2 are
unbuilt or unwired work, 4 is decisions awaiting a human, and 5 is documentation
defects. The one exception is 5.2, the numbering disagreement, which is stated
above because it changes how the table itself is read.

# From the epic reflections — what recurred

Twelve epic reflections, written 19–21 August 2026 across three projects
(`voice-studio` #1–#6 and #47, `brightpath` #1 and #9 twice, `atlas-workspace`
#296 and #301), 2,600 lines of prose, plus the later reflections a row names
explicitly (`voice-studio` #68–#69, `atlas-workspace` #375). Read one at a time
each is a war story.
Read together, a dozen causes account for nearly all of it, and the ones that
cost the most are the ones that recurred.

Same rule as the table above: **this is a projection, not a source.** Unlike the
first table, whose sources are `AGENTS.md` and `findings.md`, this one projects
over a third set that is also in this repo — the twelve files under
`docs/<project>/reflection/`. They stay authoritative for their own detail;
nothing here is a new finding, and the value is the count.

acting on it.

## The three shapes underneath the eighteen

**The cheap deterministic check runs after the expensive irreversible one.**
R2, R7, R13, R14 and SK9's runtime probe are all the same ordering defect: a
port, a `git check-ignore`, a `git rev-parse --git-common-dir`, a dirty-tree
test — each free, each deterministic, each discovered after a branch existed
and a plan review had been billed. Every one of them is a preflight that was
written somewhere else in the file. `afk validate` checks the DAG exhaustively
and the environment it is about to hand the DAG to not at all.

**Advisory output that is right and changes nothing is a gate that was never
built.** R1, R5 and the supervisor across nine epics. The supervisor diagnosed
the fast-forward, the poisoned baseline, the human gate, the prunable
checklist, and a verifier that was lying about its own report — correctly, every
time, into a log line. The plan reviewer predicted two of the worst outcomes in
the set before a token was spent. The system's most accurate components are the
ones wired to no consequence.

**`passed` means two commands exited zero.** R4 and R6 are the two ways that
bites: the check that never ran, and the defect that lives between the lanes
each check covers. Twelve epics produced six instances of the first and six of
the second, and in every single case the reading of the code — by the closeout
verifier, by a post-run `/code-review`, or by a human asking a sideways question
— is what found it. Nothing else ever did.
